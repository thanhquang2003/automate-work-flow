# DevFlow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local/server web app that drives Claude Code headless through the full software workflow (analysis → customer Q&A → breakdown → design docs → tasks/test cases → code → review → test with evidence → GitLab bugs → fix loop) and outputs company-template documents.

**Architecture:** Single Node 24 TypeScript process: Fastify HTTP server (Eta templates + htmx + SSE), SQLite via `node:sqlite`, an in-process job worker that runs a per-request stage state machine; each stage spawns `claude -p` in the request workspace, validates JSON outputs with zod, and renders documents into company templates (exceljs for xlsx, jszip+OOXML for docx). GitLab REST v4 + git CLI for branches/MRs/issues.

**Tech Stack:** Node 24, TypeScript (ESM, `tsx` for dev, `tsc` build), Fastify 5 (+ @fastify/formbody, @fastify/multipart, @fastify/cookie, @fastify/static), eta, htmx (vendored static file), zod, exceljs, jszip, archiver, vitest.

**Spec:** `docs/superpowers/specs/2026-11-04-devflow-design.md`

## Global Constraints

- Node 24, ESM, TypeScript strict. DB = `node:sqlite` (`DatabaseSync`), no native modules.
- All UI text in Vietnamese.
- `DEVFLOW_MODE=local|server`; local binds `127.0.0.1` with no auth; server binds `0.0.0.0`, requires login except `/s/*` and `/static/*`.
- Never push/merge into the repo default branch; final MR `devflow/<REQ>` → default branch is opened, not merged.
- Bug fix attempts > 3 → request status `NEEDS_HUMAN`, issue label `needs-human`.
- Test status P is rejected (downgraded to F, comment "thiếu evidence") unless ≥1 evidence file exists under `evidence/<TC-ID>/`.
- Clarify rounds max 5; review rounds per task max 3; Claude JSON-schema retries max 2.
- Survey token: 32 random bytes base64url, expiry `SURVEY_TTL_DAYS` default 14.
- `MAX_CONCURRENT_JOBS` default 1 (local) / 2 (server). Rate-limit pause default 30 min.
- `CLAUDE_MOCK=1` makes the runner use `src/claude/mock.ts` fixtures — used by all automated tests; tests never call real Claude or real GitLab.
- IDs: `REQ-001`, `F-01`, `T-01`, `TC-<FEATURECODE>-NN` (as produced by Claude), questions `Q-01`.
- Upload limit 50MB/file. GitLab tokens encrypted AES-256-GCM with `SECRET_KEY`.
- Commit after each task; commit messages end with the two attribution lines:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01N8xgo4VcKqDzy4eDXiK2WC`.

## Review Focus

1. Customer uploads the questions Excel with rows reordered, extra blank rows, or answers in merged/formatted cells → answers matched by ID column, blanks ignored, unknown IDs reported not crashed. (Task 2 test `imports answers by id regardless of row order`.)
2. Server restarts mid-stage → the stage_run left `running` is reset to `queued` and re-executed; completed stages not re-run. (Task 6 test `recovers running stage after restart`.)
3. Claude output hits subscription limit text (e.g. "usage limit reached … resets 3pm") → job paused, not failed, retried after reset. (Task 5 test `detects rate limit`.)
4. Markdown from Claude with special XML chars (`<`, `&`, quotes) and Vietnamese text → valid docx that opens (XML parses). (Task 4 test `escapes xml and keeps unicode`.)
5. Expired/unknown survey token, or a second submit after final → 404/410 page, no data change. (Task 11 test `rejects expired token`.)

Transitions: job kind `run_stage` {stage}.
